2. Now, let’s see if we understand this tiny address space we’ve constructed
(using the parameters from the question above). 
What is the highest legal virtual address in segment 0? 
0+19 = 19 (0x13)

What about the lowest legal virtual address in segment 1? 
128-20 =108 (0x6c)

What are the lowest and highest illegal addresses in this entire address space? 
Lowest: 19+1 = 20 (0x14)
Highest:108-1=107 (0x6b)

Finally, how would you run segmentation.py with the -A flag to test if you
are right?
./segmentation.py -a 128 -p 512 -b 0 -l 20 -B 512 -L 20 -A 19,108,20,107 -c

4. Assume we want to generate a problem where roughly 90% of the
randomly-generated virtual addresses are valid (not segmentation
violations). How should you configure the simulator to do so?
Which parameters are important to getting this outcome?

Let address space  = asize, then -b0 0 -B asize, l1 + l2 = 90% * asize
Base of seg0 is 0, base of seg1 is max address space
Sum of limits is 90% of address space, each l1, l2 at most asize/2

./segmentation.py -a 128 -p 512 -b 0 -l 60 -B 128 -L 55 -n 100 -c -s 3 | grep VALID | wc -l
./segmentation.py -a 128k -p 512k -b 0 -l 60k -B 128k -L 55k -n 100 -c -s 4 | grep VALID | wc -l

5. Can you run the simulator such that no virtual addresses are valid?
How?
Set the 2 limits to 0
./segmentation.py -l 0 -L 0 -c

3. How would you configure the scheduler parameters to behave just
like a round-robin scheduler?

Set the boost lower than allotment (e.g 9) so all jobs remain in highest priority, 
without -I (so that jobs that finished IO dont move imediately to the front
of the queue)

5. Given a system with a quantum length of 10ms in its highest queue,
how often would you have to boost jobs back to the highest priority
level (with the -B flag) in order to guarantee that a single long running
(and potentially-starving) job gets at least 5% of the CPU?

Every 200 ms: gets first 10ms, then CPU can be occupied by other IO jobs 
for next 190 sec, boost at 200 so long-running job gets again 10 units on CPU.
10/200=5%
./mlfq.py -n 3 -q 10 -l 0,100,0:0,100,1:0,100,1 -i 1 -S -B 200 -c

6. One question that arises in scheduling is which end of a queue to
add a job that just finished I/O; the -I flag changes this behavior
for this scheduling simulator. Play around with some workloads
and see if you can see the effect of this flag.
With -I a job that issues an IO, after it's finished moves immediately to 
front of current queue so it doesn't have have to wait for the other jobs 
to finish their allotments, gets more CPU time because it might issue
other IOs so it's good to use their IO time for other jobs and avoid
keeping the CPU idle if the others finish before this IO intensive job
